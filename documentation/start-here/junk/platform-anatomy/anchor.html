ANCHOR · Standard Operating Procedure

Single source of truth for property & project tracking
📌 v2.4 – last updated May 2026

🎯 Purpose

The ANCHOR system serves as the definitive database for property and project tracking. It manages immutable property records and tracks every interaction – from application submission to funding requests – ensuring a single source of truth for the organization’s primary operations.

📘 Key Definitions

  • PlaceCode Records – Immutable property records tied to specific physical locations.
  • Project Records – Use PlaceCode as primary key; track repairs, funding, interactions.
  • Softr – Front‑end interface (Admin, PM, Crew, Volunteer).
  • Airtable – Back‑end database where ANCHOR records reside.

⚙️ System Architecture

Airtable (back‑end) + Softr (UI). Records are updated via automations to maintain data integrity. Access is role‑based:

  • 👑 Admin – Inbox layout
  • 📋 Project Manager – Kanban view
  • 🔨 Crew / Volunteer – List views
↗️ ANCHOR interacts with: ARCHR Project Costing, ARCHR Progress Tracker, Project Documents (MOUs, contracts, insurance).

🤝 Add a New Partner – step‑by‑step

1 Add Organization Record
2 Add Personnel records
3 Create Partner Program Record
4 Run Eligibility Check

🗂️ Uses Directory + Partner Programs bases

⚠️ Current challenges

  • Manual deduplication of records
  • Terminology mismatches between orgs
  • Incomplete milestone reporting

✨ Future improvements

  • Standardized user flows
  • Enhanced reporting dashboards
  • “Never hard delete” policy → full auditability
