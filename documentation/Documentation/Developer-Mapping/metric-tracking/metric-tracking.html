📐 ARCHR Metric Tracking System

Transparent, reproducible algorithms for nonprofit metrics — with confidence tiers, not perfection.

🎯 Level 1 confidence (68%) → Level 2 (95%) → Level 3 (98%)

📌 Core Philosophy

Instead of extracting imperfect numbers from a broken system, we reverse-engineer the metrics we need — working backward from the ideal, then approximating with current data. This documentation walks through every dashboard metric in plain English, showing the formula, assumptions, and confidence level.

✅ Level 1 (68% confidence) = rough estimate, good for internal trends
✅ Level 2 (95% confidence) = high accuracy, ready for donor reports
✅ Level 3 (98% confidence) = auditable, requires perfect data hygiene

🔁 Always label metrics with confidence & last updated date

📆 1. Past Week Metrics (dashboard & weekly review)

1️⃣ Total Applications
Number of intake applications submitted in the last 7 complete days (excluding today).
COUNT(submitted_at) WHERE submitted_at BETWEEN (CURRENT_DATE - 7 days) AND (CURRENT_DATE - 1 day)
📐 Confidence Level 2. Uses complete days to avoid partial-week noise. Excludes test submissions.
2️⃣ Assessments Assigned
Property assessments created or assigned to an assessor in the past week.
COUNT(property_assessments) WHERE assigned_at OR created_at in past 7 days
🔧 If `assigned_at` is NULL, fallback to `created_at` (proxy for assignment).
3️⃣ Assessments Completed
Assessments marked complete in the past 7 days (throughput, not when they were assigned).
COUNT(property_assessments) WHERE assessment_completed_at BETWEEN past_week_range
📈 Key for measuring team productivity, regardless of when assessment was started.
4️⃣ Average Triage Score
Weighted urgency score (0–100) for assessments completed last week. Higher = more critical.
Formula: (Urgent conditions × 12.5) + (estimate size percentile × 30) + (Helene-related × 30), capped at 100
🧠 Triage = 40% urgency (7 conditions), 30% repair estimate size, 30% disaster priority. Capped at 100.
5️⃣ Total Individuals Served (household size sum)
Sum of household sizes from applications submitted in the past week.
SUM(household_size) FROM intake_submissions IN past_week_range
👥 Used for grant reporting & measuring total human impact, not just households.
6️⃣ Income Breakdown (past week)
Applications categorized by annual income bracket ($0, $1–15k, $15k–30k, $30k–50k, $50k–75k, $75k+).
CASE based on has_income + gross_annual_income + income_records (annualized)
💰 Zero-income affidavit = $0 bracket. Uses calculator method if gross_income missing.
7️⃣ County Breakdown
Geographic distribution of applications (Buncombe, Madison, Henderson, etc.)
Infer county from home_city, home_zip, or explicit home_county field.
🗺️ Future improvement: add explicit county picker in intake form.
8️⃣ Issue Type Pie
Primary repair category selected per application (unable_to_stay, no_hvac, no_kitchen, etc.)
DISTINCT ON (submission_id) ORDER BY submission_repair_categories.id
🥧 Uses first-selected category as primary. Helps with contractor/resource planning.

📈 2. All‑Time Metrics (since inception)

9️⃣ Total Jobs
Total work orders ever created (all statuses).
COUNT(work_orders)
📦 Each job = one work_order record. May contain multiple tasks.
🔟 Jobs in Progress
Work orders with status: in_progress, assigned, planned.
COUNT(work_orders WHERE status IN ('in_progress','assigned','planned'))
🏗️ Current active workload, excludes completed/cancelled.
1️⃣1️⃣ Jobs Completed
Successfully finished work orders (final inspection & sign-off).
COUNT(work_orders WHERE status = 'completed')
✅ Primary success metric for the program.
1️⃣2️⃣ Jobs Withdrawn/Rejected/Ineligible
Negative outcomes: withdrawn by applicant, rejected by org, or ineligible.
UNION of intake_submissions WHERE submission_status IN ('withdrawn','denied') + cancelled work_orders
⚠️ Tracks pipeline leakage; helps improve intake screening.
1️⃣3️⃣ Average Job Cost
Mean cost of completed jobs (actual expenses, not estimates).
AVG(cases.total_actual_cost) WHERE work_orders.status = 'completed' AND cost > 0
💰 Also returns median, min, max for robust budgeting.
1️⃣4️⃣ All Jobs Income Breakdown
Income distribution of applicants whose jobs were completed (all time).
Same logic as past‑week income breakdown, but filtered by completed work orders.
📊 Mission alignment: shows % of low‑moderate income households served.
1️⃣5️⃣ All Jobs County Breakdown
Geographic distribution of completed work (where the repair happened).
Same county inference as past week, limited to completed jobs.
📍 May differ from application county if applicants move or are served by partner orgs.
1️⃣6️⃣ Highest & Lowest Job Cost
Extreme values for completed jobs (to detect outliers/complex projects).
MAX(total_actual_cost) and MIN(total_actual_cost) for completed jobs, cost > 0
🏆 Useful for case studies and identifying large-project capacity.

🤝 3. Organization‑Specific Metrics (per partner org)

Each coalition organization gets a filtered view of the same core metrics, based on application_assignments and case ownership.

1️⃣7️⃣ Total Jobs (org)
All work orders linked to cases assigned to that org.
COUNT(work_orders) JOIN application_assignments WHERE organization_id = target
1️⃣8️⃣ Jobs in Progress (org)
Active jobs for the organization.
Same as #10, filtered by organization.
1️⃣9️⃣ Jobs Completed (org)
Completed jobs for the organization.
2️⃣0️⃣ Jobs Suggested
Pending assignments not yet claimed or rejected (expiration‑aware).
COUNT(application_assignments WHERE status='pending' AND expires_at > NOW())
⏳ Measures organizational responsiveness.
2️⃣1️⃣–2️⃣3️⃣ Assessments Assigned / Completed / Pending
Assessment workload for the org’s assigned cases.
COUNT(property_assessments) with same completion logic as metrics #2–3, filtered by org.
2️⃣4️⃣–2️⃣6️⃣ Highest, Lowest, Average Job Cost (org)
Cost extremes and average for completed jobs, per organization.
2️⃣7️⃣–2️⃣8️⃣ Income & County Breakdown (org)
Demographic and geographic distribution of the org's completed jobs.
📌 All org‑specific metrics use the same source tables (cases, work_orders, property_assessments) but filter by application_assignments.organization_id.

🎯 Confidence Tiers – How We Label Data

Instead of waiting for perfect data, we label metrics by accuracy level. This lets us publish dashboards now while improving data quality over time.

🟡 Level 1 (68% confidence) – “Rough Estimate”
Derived from incomplete or inferred data. Good for internal trends, not for external reporting.
Example: county breakdown using zip code inference before explicit county field exists.
🟢 Level 2 (95% confidence) – “High Accuracy”
Based on complete, validated data sources. Ready for donor reports and dashboards.
Example: total applications, assessments completed, job counts.
🔵 Level 3 (98% confidence) – “Audit‑Ready”
Requires perfect data hygiene, reconciliation, and third‑party verification.
Example: total funding disbursed by fiscal year, after external audit.
📢 Transparency rule: Every metric on a dashboard must show its confidence level and the date it was last refreshed.

⚙️ Implementation Roadmap

Instead of reverse‑engineering the existing Airtable mess, we:

  • ✅ Metric first – define what we need to know
  • ✅ Algorithm second – write formula in plain English + SQL
  • ✅ Data source third – locate closest existing field, add confidence note
  • ✅ Automate fourth – build scheduled queries & dashboards (Softr / PowerBI / custom)
