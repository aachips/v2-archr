# ARCHR v2 — Session Summary: October 29, 2026

## What We Accomplished

### 1. SuperAdmin Dashboard — Fixed Rendering & Auth
- **Root cause:** `SuperAdminView.vue` had a Vue template scoping bug — `<tr v-for="org">` only applied to the first row, leaving the edit-row's `org` reference undefined. Fixed by wrapping both rows in `<template v-for="org">`.
- **Auth headers:** Every `fetch()` call in `SuperAdminView` was missing the `Authorization: Bearer <token>` header. Added token to all GET and POST requests (`loadData`, `searchUsers`, `apiPost`).
- **Airtable warning isolation:** Added `needsAirtable` computed property — the "Airtable isn't configured" warning now only shows on Airtable-dependent views (Search, Marketplace, Tasks, Documents). SuperAdmin, Requestor, Assessor, WhoAmI, Welcome, Profile no longer show it.
- **`.env` file:** Created `vue-view/.env` with `VUE_APP_AIRTABLE_API_KEY` and `VUE_APP_AIRTABLE_BASE` copied from `app/.env`, so the Vue build can configure Airtable properly.

## Key Architecture Decisions
- **Role level normalization:** Database `roles.role_level` uses old 0–80 scale; Vue maps to consolidated 0–3 via `$ROLE_LEVEL_MAP` in `vue_api/auth.php` and `archr_get_permission_level()` in `permissions.php`.
- **Role code normalization:** PostgreSQL stores roles as UPPERCASE (`SUPER_ADMIN`); all PHP queries use `LOWER()` + `strtoupper()` for consistent matching. Underscores normalized to hyphens (`super_admin` → `super-admin`).
- **Role-specific capability overrides:** `WhoAmI.vue` uses `ROLE_CAPABILITY_OVERRIDES` to grant/remove capabilities per role beyond their level defaults (e.g., Requestor gets `upload_documents` but not `log_hours`; Envoy gets `view_all_orgs`).
- **Vue template v-for scoping:** When using `v-for` on table rows with expandable edit rows, wrap both `<tr>` elements in `<template v-for>` to keep the loop variable in scope for both rows.
- **Airtable vs PostgreSQL views:** Views that don't need Airtable data (SuperAdmin, Requestor, Assessor, WhoAmI, Welcome, Profile, ActivityLog) render regardless of Airtable configuration. Only Search, Marketplace, Tasks, Documents, ComponentLibrary require Airtable.
